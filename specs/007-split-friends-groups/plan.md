# Implementation Plan: Split with Friends, Groups & Expenses

**Branch**: `007-split-friends-groups` | **Date**: 2026-05-26 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/007-split-friends-groups/spec.md`

---

## Summary

Add group-based expense splitting to the PaySplit app. Users can create named groups, invite friends as members, record shared expenses with three split methods (equal / custom amount / percentage), and view auto-computed balance summaries showing who owes whom. A lightweight direct-split shortcut handles two-party splits without requiring a formal group. The feature extends the existing MongoDB + Express + Next.js stack with no new infrastructure. All UI follows the existing dark-glass design system with full mobile responsiveness.

---

## Technical Context

**Language/Version**: TypeScript (Node 20 LTS / Next.js 15 App Router)

**Primary Dependencies**:
- Backend: Express.js, Mongoose, Socket.IO, Zod (validators), express-rate-limit
- Frontend: Next.js 15 App Router, Vanilla CSS, `socket.io-client` (already present)

**Storage**: MongoDB via Mongoose — three new collections: `groups`, `expenses`, `expense_splits`

**Testing**: Vitest (unit + integration), Playwright (e2e) — consistent with existing test setup

**Target Platform**: Web (desktop + mobile browser) — Next.js SSR + CSR hybrid

**Performance Goals**:
- Expense list + balance summary loads in under 2s for groups with ≤50 expenses (SC-006)
- Balance notifications delivered within 30s via existing Socket.IO (SC-005)

**Constraints**:
- Single currency per group (v1)
- Max 50 members per group
- No settlement/repayment flow (v1)
- No group deletion (v1)

**Scale/Scope**: ~5 new backend files, ~8 new frontend components, ~3 new pages/routes

### New Pages & Components

#### `/groups` — Groups List Page
- Full-width layout with sidebar (same `dashboard-page` shell)
- Animated liquid orb background (green tint, matches friends page)
- **Header**: "Your Groups" title + green "Create Group" CTA button (top-right)
- **Groups grid**: `auto-fill, minmax(300px, 1fr)` responsive grid
- **GroupCard**: Glass card with group name, member count avatars (stacked, max 5 shown), total balance pill (green = you're owed, red = you owe), hover lift + brand-accent border glow
- **Empty state**: Centered illustration text + "Create your first group" CTA
- **"+ Direct Split"** shortcut button in the header for quick two-party splits

#### `/groups/[groupId]` — Group Detail Page
- **Group header**: Group name, description, member avatar row, "Add Members" + "Add Expense" buttons
- **Two-column layout** (desktop): left = Balance Summary card, right = Expense List
- **Single-column** (mobile ≤768px): Balance Summary stacked above Expense List
- **Balance Summary card**: Per-member balance rows showing "Alice owes Bob ₹450" with colored amount badges; "All settled up 🎉" empty state
- **Expense List**: Chronological cards — expense title, date, who paid, total amount, split preview chip ("Split equally", "Custom", "By %")
- Hover on expense card shows per-member split breakdown tooltip

#### Modals (all follow `friends-modal-*` pattern)

**CreateGroupModal**:
- Group name input (required)
- Optional description textarea
- Member search (reuses `friends-search-input` style) — shows friend list, click to add
- Member chips row with ✕ remove button
- "Create Group" primary button

**AddMembersModal**:
- Friend search input
- Already-member indicator on search results
- "Add" button per result
- Confirmation with count ("2 members added")

**AddExpenseModal** (richest modal):
- Title input
- Amount input (₹ prefix, large font for emphasis)
- Date picker (HTML date input styled to match theme)
- Payer selector (dropdown or segmented control from group members)
- Split method toggle: `Equal | Custom | Percentage` (segmented control matching `friends-tabs`)
  - **Equal**: Shows auto-computed share per member (read-only preview)
  - **Custom**: Editable amount input per member row; running total indicator (green when matched, red when off)
  - **Percentage**: Editable % input per member; percentage total indicator
- "Add Expense" primary button (disabled until validation passes)

## Verification Plan

### Automated Tests

```bash
# Backend unit tests (services + validators)
cd backend && npm run test

# Backend integration tests (API endpoints with test DB)
cd backend && npm run test:integration

# Frontend unit tests (components + split calculation logic)
cd frontend && npm run test

# E2E (Playwright)
cd frontend && npx playwright test
```

**Key test scenarios**:
- Group create with valid/invalid payloads → 201 / 400
- Member add — duplicate member silently skipped
- Expense create — equal/custom/percentage split calculations
- Expense create — custom split amounts don't sum → 400
- Balance aggregation — net amount between users correct after multiple expenses
- Direct split — auto-creates isDirect group, reuses existing on second call
- Auth guard — all endpoints return 401 without session cookie
- Rate limiter — 11th group create in 15min returns 429

### Manual Verification

1. Create group with 3 friends → verify all 3 receive `group_update` Socket.IO event
2. Add expense (equal split, 3 members) → verify each member sees ₹X.XX share
3. Add expense (custom split, amounts deliberately mismatched) → verify error message in modal
4. Add expense (percentage split, 40%/60%) → verify correct cent amounts calculated
5. View balance summary → verify "Alice owes Bob ₹450" is arithmetically correct
6. Direct split via Friends page → verify isDirect group created, both users see balance
7. Mobile (Chrome DevTools 375px) → verify hamburger sidebar, single-column layout, modal fits screen
8. Empty group state → verify "All settled up" shown when no expenses exist
